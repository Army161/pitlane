# PITLANE agent workspace and completion scope

Jeremy requested continuous completion on 5 October 2026, including a polished SaaS application, agent chat, teams and sprints. App 5 means the fully built real product, not another app. This extends the approved v0.2 design without weakening its inspection, privacy or billing invariants. Existing workspace and original garage design are the starting point. The owner explicitly requests execution without intermediate approval pauses.

## User outcome
Solana integration teams book bounded inspections, review private receipts and costs, collaborate in project teams and organize follow-up work in sprints. Agent conversations explain actual authorized evidence. Chat does not create a safe finding, alter assertions, sign or broadcast transactions, or execute arbitrary code. Builder agents in this development task are real delegated workers; the product must not invent autonomous builders or activity.

## Agent workspace
Persist project-scoped conversations, append-only messages, sprint records and work items with actual authors, timestamps, states and links. Current membership authorizes every operation; developers/admins write and viewers read. User messages survive provider failure. AI replies require an explicitly configured real provider, are separately labeled and cannot have tools. Without a provider, show unavailable and retain the user's message; never substitute a fake response. Bound messages, context, responses, deadlines and per-project AI rate/cost allowance. Exclude raw artifacts and secrets from prompts. Evidence links are scoped and checked, and a deleted/revoked project cannot be read through chat. Sprint work is explicitly assigned and changed by authorized people; no synthetic completion or team activity.

## Completion work
1. Finish validated hosted service startup, graceful drain and Node/Next standalone packaging.
2. Complete durable payment expiry, inbox retries/quarantine, subscription mappings and external adjustment reconciliation; live payment activation remains an independently verified gate.
3. Complete retention, orphan cleanup, expiry responses and authorized tenant deletion.
4. Build agent conversations and actual sprint/team records and integrate their responsive screens.
5. Bind receipts to exact manifests; demonstrate database and object backup/restore; expand browser journeys and independent review.
6. Provide clean source, setup/deployment contracts and recorded acceptance evidence. Live activation requires actual dedicated resources, two authorized independent RPC upstreams, private storage/auth and verified worker network isolation. Never present fixtures or empty integration adapters as live data.

Parallel execution uses disjoint file ownership and migration slots 029 startup, 030 billing, 031 retention and 032 collaboration. The coordinator integrates shared runtime/API/UI files and runs final checks after all changes.
